# 概念 B「校園冒險狀態列」設計規格

預覽：`index.html`（首頁、停車、課業三個 393×852 畫面並排），截圖 `preview.png`。

## 1. 設計理念（三點，含真實物件對照）

1. **整個 App 是一組「選單視窗」。** 真實物件：16 位元時代角色扮演遊戲的狀態／道具選單。在選單裡，資訊永遠裝在「雙線框視窗」裡，視窗左上角貼一張名牌（標題）。本案每個資訊群組都是一個視窗，名牌就是群組標題（角色狀態、今日任務、待辦作業、補給站、選擇目的地、任務日誌）。
2. **選中的那一列用 ▶ 游標加底色帶表示。** 真實物件：選單的反白選項。首頁游標停在「下一堂」，停車頁停在「剩最多的停車場」，課業頁停在「今天（週三）」。游標是全 App 唯一的「目前位置」記號，其他地方不用箭頭。
3. **數量一律畫成分格數值條。** 真實物件：角色狀態的 HP 條（10 格）。車位剩餘比例、作業剩餘時間都用同一種 10 格條，讀者學一次就懂；數字與狀態文字同時標出，不靠條的長度單獨傳達。

## 2. 骨架

- **首頁＝角色狀態欄**（由上而下）：角色狀態（頭像、名字、天氣＝場景資訊）→ 今日任務（課程＋地點）→ 待辦作業（時間條）→ 補給站（機車車位）→ 底部對話框（行事曆）。
- **停車＝選擇目的地地圖選單**：選擇目的地（總計 109）→ 校區簡圖（四個標記，游標與框線指向目前選項）→ 機車停車場選單（四列）→ 汽車停車場 → 狀態說明。
- **課業＝任務日誌**：任務日誌（本週、期中考週）→ 本週課表（週一到週五，今天有游標）→ 作業列表（四筆）。
- 三頁共用：頂部狀態列、底部 5 格「指令列」，目前分頁是被按下的金色格。三頁的視窗數量、順序與重點都不同，不是同一個骨架換內容。

## 3. 刻意避開清單

- 系統灰底＋白色圓角卡片、模糊陰影、藍色單一強調色、SF 字型的範本感。
- 只換配色的做法：視窗結構（雙線框、缺角、名牌）才是主角。
- 抄既有遊戲的名稱、角色、配色、介面版型；不寫「勇者」「打怪」之類台詞。
- 每頁同一骨架；emoji；「AI」字樣；假功能；英文口號。
- 像素中文用於內文（太小難讀）；一字一行的擠斷。

## 4. 字型與授權

- 像素字：俐方體 11 號 Cubic 11（SIL OFL 1.1，可商用），自 `https://cdn.jsdelivr.net/gh/ACh-K/Cubic-11@v1.500/fonts/web/Cubic_11.woff2` 載入；只用於名牌、標題、數字、標籤。字級僅 12／24／36 px（12 的整數倍）。
- 內文：`-apple-system, "PingFang TC", "Noto Sans TC", sans-serif`，皆 ≥15px。
- 唯一外部資源即上列字型網址。
- SwiftUI 實作時把 `Cubic_11.ttf`（同授權）放進 App bundle，Info.plist 的 `UIAppFonts` 註冊，內文用系統字型。

## 6. 紋樣／元件「只用在哪裡」

| 元件 | 遊戲選單中的它是 | 只用在 |
|---|---|---|
| 雙線框缺角視窗（外框 paper、內線 slate） | 資訊視窗 | 所有資訊群組 |
| 金框＋紙色內底的視窗 | 底部對話框 | 首頁底部行事曆 |
| 金色名牌 | 視窗名稱標籤 | 每個視窗左上角，僅放標題 |
| ▶ 游標（閃爍） | 目前選項 | 每頁一處：下一堂／剩最多停車場／今天 |
| ▼ 繼續符號（閃爍） | 對話框「下一則」 | 僅首頁對話框 |
| band 色帶 | 反白列 | 只配合游標出現 |
| 10 格數值條 | HP 條 | 車位量、作業剩餘時間 |
| 斜紋底軌（ember 2px 棋盤斜點） | 無法選取／空 | 只用在滿位的數值條 |
| 星點底紋（night 2px 點，32px 重複） | 場景背景 | 只在畫面底（視窗外），內文區不鋪 |
| 名牌色塊「標籤」 | 狀態 icon 小旗 | 只做狀態／倒數（充足、緊張、下一堂 28 分鐘後） |
| 實色位移陰影（ink 4px） | 可按指令 | 底部分頁格（未選）、「更新」按鈕；被選中的分頁格＝按下，位移 4px 蓋住陰影 |
| 12×12 點陣圖示 | 指令圖示 | 分頁列（P 牌、書、房、校舍、滑桿）、天氣雲 |
| 7×7 狀態形 | 狀態符號 | 標籤、地圖標記、補給站、說明列 |
| 20×20 頭像（2px 一格） | 角色肖像 | 只在首頁角色狀態 |

網格：1 像素＝2pt；缺角（4px／2px 階梯）、框線、陰影、點陣一律 2 的倍數，點陣一律 `image-rendering: pixelated`；全檔無 blur 的 box-shadow。

## 7. 動態規則

- 招牌動態只有一個：**游標閃爍**（▶ 與 ▼ 同步），`animation: blink 1s steps(1,end)`，離散兩格。
- 無緩動、無漸變、無位移動畫。
- `@media (prefers-reduced-motion: reduce)` 關閉游標閃爍，游標常亮。
- SwiftUI：以 `TimelineView(.periodic)` 每 0.5 秒切換不透明度；`accessibilityReduceMotion` 為真時停用。

## 8. SwiftUI 實作要點

- **元件拆分**：`PixelWindow`（容器＋名牌）、`PixelPlate`、`MenuRow`（游標＋色帶＋內容）、`SegmentBar(value, total=10, tint)`、`StatusChip(state)`、`PixelButton`（按下位移）、`CommandTabBar`、`DialogBox`、`PixelIcon(map:)`。
- **像素框怎麼畫**：自訂 `Shape`（`NotchedRect`）以 `Path` 產生階梯缺角（4pt／2pt 整數格）；`PixelWindow` = 外 `NotchedRect(paper)` → 內縮 2pt `NotchedRect(night)` → 內縮 4pt `stroke` 2pt（slate）。不用 `cornerRadius`、不用 `shadow(radius:)`。
- **用 Canvas 的**：點陣圖示與頭像（`Canvas` 讀 `[String]` 點陣字串＋色票，逐格 `fill(Path(CGRect))`，`.interpolation(.none)`）、`SegmentBar`、校區簡圖、斜紋底軌（`Canvas` 畫 2pt 棋盤）、星點底。其餘用一般 `View`。
- 位移陰影：`PixelButton` 以 `ZStack { Rectangle(ink).offset(y:4); face }`，按下時 face `offset(y:4)`。
- 像素字只給 `Font.custom("Cubic 11", size: 12/24/36)`；中文內文 `.system`，並套 Dynamic Type（像素字固定、不隨 Dynamic Type）。
- 狀態顏色一律由 `enum Status { sufficient, tight, full }` 同時驅動形狀、顏色、文字，避免只靠色。

## 9. 文案語氣

清楚、實用、陳述式。只借「結構」詞彙：任務、待辦、補給站、目的地、日誌。每頁至多一句帶遊戲味文案：本案實際只有各頁的視窗名稱帶這種味道（如「補給站」「選擇目的地」），內文數字與地點一律如實，沒有台詞。上限：不使用角色扮演口吻（勇者、打怪、升級、經驗值）。

## 10. 自評缺點

1. 深藍底加金色強調，在戶外強光下對比雖達標但整體偏暗；沒有提供淺色版。
2. 12px 像素字（節次、數值小標、地圖標籤）接近下限，長時間閱讀不友善；重要資訊已改用內文字體。
3. 校區簡圖是示意圖，沒有真實地理比例；課表中除「今天」外的課名、節次為示意資料。
4. 停車頁與課業頁底部仍有約 40–60px 空白，是為了讓三頁都不被擠到指令列；可再加內容或拉高列距。
